# 眼科指南配套门诊病历

本 skill 是本项目新整理的工作流，并非从 eyedisease 仓库找到的原有 skill。
结构参考 lunansq/eyedisease 的糖尿病视网膜病变Ⅲ期 Word 模板；来源和适用限制见 [来源说明](references/source.md)。

## 启用范围

用户要求“按指南生成门诊病历”“生成某病初诊/复诊模板”或将指南资料配套为门诊记录时使用。
默认生成**可编辑的疾病模板**，不是已发生就诊的正式病历。
用户提供就诊事实并要求整理时，才生成**患者病历草稿**，由接诊医师核实签署。
“后续配套”只建立后续流程，不代表要求立即批量重做全部既有指南。

## 输入与核对

1. 确认疾病、初诊或复诊、指南版本；优先使用本项目已审核的原文提取表，并回到 PDF 核对关键条件、数值、剂量和原文页码。
2. 记录来源类型：指南/专家共识/意见书/解读/单篇研究。解读不能假称原始指南；研究结果不能自动升级为推荐。
3. 使用原文印刷页码；无印刷页码则明确写“PDF 第 X 页”。标题年份与刊载年份不同的同时注明。没有原文的不得编造页码。
4. 患者草稿仅采用用户提供的症状、病史、左右眼检查结果和实际医嘱。必要信息不足时，先列出缺失项目，继续整理可确定部分。

## 工作流程

1. 建立“指南建议—适用条件—所需患者信息—病历栏目—原文出处”的对应表。
2. 按 [栏目模板](references/template.md) 生成初诊模板；有复诊需求时增加疗效、用药依从性、不良反应、检查趋势与方案调整栏目。
3. 将疾病特异的诊断标准、鉴别诊断、分层、检查、治疗条件、禁忌、特殊人群、随访和急诊提示纳入对应栏目。
4. 模板用条件句表达处理分支；具体患者未满足适用条件、关键资料不全或尚未由医师决定时，不输出确定的处方或已实施治疗。
5. 单独输出“指南依据与核对表”，每条关键建议写年份、原文页码、来源类型。病历正文保持可用于记录的栏目格式；依据表注明不复制进患者病历。
6. 按核对清单完成检查，保存可编辑 Markdown；需要 Word 时输出 DOCX。文件生成后实际读取，检查中文、特殊符号、表格、分页与左右眼一致性。
7. 配套 PPT、流程图、卡片沿用既有流程；仅请求病历时，不额外重做所有成品。

## 事实与证据规则

- 患者信息缺失写“待补充/未提供”；检查尚未完成写“未查/待查”，不得填“正常”“阴性”“无过敏史”。
- 指南对某项建议没有说明写“原文未明确”。这与“患者资料未提供”严格区分。
- 不复制来源模板中的阳性或阴性眼底示例作为患者实际所见。不生成虚假的医师签名、患者理解、已宣教、知情同意或治疗完成记录。
- 明确 OD/右眼、OS/左眼、OU/双眼；不要因一眼结果推断另一眼。保留视力计量方法、眼压单位、检查方法和时间。
- 诊断或严重程度不满足条件时写“疑似/待排/待进一步评估”，不靠模板标题自动确诊。
- 传统分期与国际分级分别标注；无可靠依据不互相换算。糖网病“Ⅲ期”不直接等同于国际分级的重度 NPDR。
- 剂量、途径、频次、疗程、单位、阈值、严格/非严格不等号和推荐等级逐项核对原文。原文没有的剂量、儿童上限或肾功能调整不补编。
- 存在相互冲突的指南表述时列明各自来源、适用人群和待核实点，不擅自合并阈值。
- 抗感染、糖皮质激素、免疫抑制及眼内治疗等方案必须保留其原文适应证和相关禁忌；不以疾病标签自动开具统一方案。
- 原模板没有指南出处，因此只能作为结构参考，不能作为诊断和治疗的证据。

## 输出与隐私

- 无患者信息时：疾病专用初诊模板、按需复诊模板、指南依据与核对表。
- 有患者信息时：患者病历草稿、缺失/矛盾信息列表、独立的依据核对表。推荐方案和实际执行医嘱分开。
- 无患者身份信息的通用疾病模板可随指南主题归入锦集。真实患者资料及生成的患者病历保持私有，不上传公共 GitHub 仓库，也不并入公开合集；若当前只有公开下载渠道，应说明限制并选择可用的私密交付方式。
- 自动保存环境文件；最终提供可用下载入口，不用环境路径冒充下载链接。

## 交付前核对

- [ ] 主诉、病程、检查、诊断、处理与左右眼一致，无自动填充的真实体征。
- [ ] 病例缺失值与原文未明确分开，未查内容未写阴性。
- [ ] 诊断条件、分层、适用人群、禁忌、特殊人群和随访按原文核对。
- [ ] 每条关键建议有来源类型、年份、页码；剂量、单位、阈值及等级未变。
- [ ] 原模板示例、单篇研究发现、指南建议、患者事实均已区分。
- [ ] 实际诊疗和拟议方案分开，未虚构签名或知情同意。
- [ ] 可编辑文件能够实际读取；公开交付文件不含患者资料。
